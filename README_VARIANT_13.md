## Сборка и запуск

Нужны C++17, CMake 3.10+, SQLite и потоки. Команды выполняются из корня проекта:

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
./build/rest_server
```

В Windows исполняемый файл может лежать в build/Debug/rest_server.exe.
Без CMake на macOS: `clang++ -std=c++17 -pthread main.cpp -lsqlite3 -o rest_server`.
Сервер использует порт 8080 и создаёт data/rest.db относительно текущего каталога.
Для веб-коллекции в другом терминале: `python3 -m http.server 8093 --bind 127.0.0.1`.
Откройте http://localhost:8093/frontend/index.html.

## Демонстрация

1. В веб-коллекции выберите вход и отправьте user1 / user1.
2. Выберите индивидуальный расчёт; в пресете уже стоит вариант 13.
3. Отправьте запрос: результат 75%, 10 л/100 км, 0.15 денежных единиц/км.
4. Укажите total_km_driven=22501: HTTP 400, так как 22501/15 > 1500.
5. Откройте индивидуальную историю: корректные запросы сохранены.
6. Войдите как admin1 / admin1, нажмите «20 тестов автопарка», отправьте запрос.
7. Исходные встроенные 20 тестов также доступны отдельной кнопкой.

## Контракт

`POST /api/v1.1/works/calc-individual`, заголовок `Authorization: Bearer <TOKEN>`.

```json
{"total_vehicles":20,"active_vehicles_day":15,"total_fuel_consumed":300,"total_km_driven":3000,"average_fuel_price":1.5}
```

```json
{"utilization_rate_percentage":75,"average_consumption_per_100km":10,"cost_per_km":0.15000000000000002}
```

Разница последнего десятичного разряда связана с double. Значения не округляются до двух знаков.
Пять уникальных обязательных числовых полей, неизвестные ключи запрещены.
Машины — положительные целые значения в диапазоне int, активных не больше общего числа.
Топливо, пробег и цена — конечные положительные числа; пробег/активных <=1500.
Промежуточные результаты не должны превышать диапазон double.
Ошибки входа возвращают HTTP 400 с полем error, без токена — 401.

## Тестирование

- `ctest --test-dir build --output-on-failure`: автономные 20 проверок варианта.
- `GET /api/v1.1/admin/run-tests-individual`: те же 20 проверок через API (admin/owner).
- `GET /api/v1.1/admin/run-tests`: исходные 20 системных тестов.
- `python3 tests/http_tests.py`: 70 HTTP-проверок. Выполнять в отдельной копии проекта с тестовой БД: сценарий регистрирует и удаляет тестового пользователя, меняет его пароль и создаёт расчёты. На рабочей БД не запускать.

Протоколы фактического запуска: tests/*_results.json.
Автономный набор не меняет базу данных.

## Изменения

- variant_mine.hpp: parse, validate, calculate, to_json, только стандартная библиотека.
- task.hpp: подключение варианта, 20 автопроверок и контроль записи в БД.
- frontend/index.html: пример запроса автопарка и запуск тестов.
- main.cpp: сохранение подробного тела ошибок.
- auth.hpp/public.hpp: различение 401/403; admin управляет собой и user, но не чужими admin/owner; 404 при смене пароля отсутствующей записи.

Истории обоих модулей используют общую таблицу works; публичная история открыта по исходному ТЗ.
Счётчик failed_validations исходного проекта не учитывает отклонённые индивидуальные запросы.
